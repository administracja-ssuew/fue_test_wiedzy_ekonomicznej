## Data Storage

**Databases:**

**Primary: Supabase PostgreSQL**
- Connection: Via Supabase project URL (`VITE_SUPABASE_URL`) and anon key
- Client: `@supabase/supabase-js`
- Schema: `SUPABASE_SCHEMA.sql` (run in Supabase SQL editor)

**Tables:**
- `public.profiles` - User profiles extending auth.users
  - Fields: id (UUID), full_name (text), city (text), university (text), role (text), verified (boolean), created_at (timestamp)
  - Access: Row-level security (RLS) policies for users and admins

- `public.quiz_sessions` - Quiz session management
  - Fields: id (UUID), stage (text: 'regional' or 'national'), city (nullable), status (text: 'waiting'/'active'/'finished'), current_module (int), current_question (int), started_at, ended_at, created_by (UUID ref), created_at
  - Tracks regional (city-based) and national (top 5 from each city) competition stages

- `public.attempts` - Quiz attempt records (participant answers)
  - Fields: id (UUID), session_id (UUID ref), user_id (UUID ref), answers (JSONB array), total_score (int), completed (boolean), completed_at, created_at
  - Answer format in JSONB: `[{qId, module, picked, correct, pts}, ...]`
  - Unique constraint: one attempt per user per session

**Local Storage (Demo Mode):**
- When Supabase credentials missing, app uses localStorage fallback
- Keys used: `fue_users`, `fue_current_user`, `fue_sessions`, `fue_active_session`, `fue_attempts`
- Demo mode controlled by `DEMO` flag in `src/lib/supabase.js`

## Row-Level Security (RLS) Policies

All tables have RLS enabled (`SUPABASE_SCHEMA.sql` lines 65-92):

**profiles table policies:**
- Select: Users see own profile OR admins (city_admin, global_admin) see all
- Insert: Users can only insert own profile
- Update: Admins can update
- Delete: Admins can delete

**quiz_sessions table policies:**
- Select: All authenticated users can read sessions
- Write: Only admins can create/update

**attempts table policies:**
- All operations: Users can only access own attempts
- Select: Admins can read all attempts

**Setup Instructions:**
1. Create Supabase project
2. Set `VITE_SUPABASE_URL` and `VITE_SUPABASE_ANON_KEY` in `.env`
3. Run `SUPABASE_SCHEMA.sql` in Supabase Dashboard → SQL Editor
4. Optionally grant admin roles via manual UPDATE:
   ```sql
   update public.profiles
     set role = 'global_admin'
     where id = 'uuid-here';
   ```

## Data Flow

**User Registration:**
1. User fills form in RegisterScreen (`src/App.jsx` lines 756-812)
2. `registerUser()` creates auth.users + profiles table entry
3. In demo mode: stores in localStorage under `fue_users` key
4. User awaits admin verification before quiz access

**Quiz Session:**
1. Admin or verified participant initiates session via `createSession()`
2. Session created in `quiz_sessions` table with stage, city, status
3. Session marked "waiting" initially, "active" during quiz, "finished" after
4. Participant answers questions, answers stored locally in React state

**Attempt Recording:**
1. On quiz completion, `saveAttempt()` writes to `attempts` table
2. Stores: session_id, user_id, answers (JSONB), total_score, completed (true)
3. In demo mode: stored in localStorage under `fue_attempts` key
4. Admins query `getSessionAttempts()` to see results with participant profiles
