# Quick 261026-o0s — CLI do bazy przez Management API

**Cel:** wgrywanie sekcji SQL i zapytania do bazy z terminala (`npm run db:*`) bez Supabase CLI, `psql` i hasła do bazy.

**Podejście:** Supabase Management API (`https://api.supabase.com/v1`) z osobistym tokenem dostępu
(`SUPABASE_ACCESS_TOKEN` w `.env`, plik w `.gitignore`). `POST /projects/{ref}/database/query` wykonuje SQL
jako właściciel bazy. Ref projektu z `VITE_SUPABASE_URL` (prod) lub `VITE_SUPABASE_URL_STAGE` (`--stage`).
Bez nowych zależności — `fetch` i `readline` z Node.

## Zadania

1. `scripts/lib/db-cli.js` — czyste funkcje: `parseEnv`, `upsertEnv`, `projectRefFromUrl`, `extractSection`,
   `isReadOnlySql`, `parseArgs`. Testy `scripts/lib/db-cli.test.js` (vitest).
2. `scripts/db.js` — podkomendy:
   - `login` — pyta o token, sprawdza go (`GET /projects`), zapisuje do `.env`;
   - `status [--stage]` — projekt (nazwa, region, stan), wersja Postgresa, wgrane `schema_marker_*`, liczba połączeń;
   - `query "<sql>" [--stage]` — wynik jako tabela; zapis na prod wymaga potwierdzenia;
   - `sql <plik> | --section N [--stage] [--yes]` — podgląd + potwierdzenie (na prod trzeba wpisać `PROD`).
3. `package.json`: `db:login`, `db:status`, `db:query`, `db:sql`.

## Weryfikacja

- `npm test` zielone (w tym nowe testy).
- `npm run db:status` bez tokenu → czytelny komunikat „uruchom npm run db:login”, kod 1.
- `npm run db:sql -- --section 45` → wycina dokładnie linie sekcji 45 (podgląd), bez tokenu nic nie wysyła.
